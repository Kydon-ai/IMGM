# Node 模型下载未使用 Windows 用户代理导致连接超时复盘

## 一、问题现象

执行 `npm run models:download` 时，模型下载失败：

```text
TypeError: fetch failed
cause: ConnectTimeoutError
code: UND_ERR_CONNECT_TIMEOUT
```

堆栈落在 Transformers.js 的 `AutoTokenizer.from_pretrained()`，也就是访问 Hugging Face Hub、读取模型文件元数据的阶段。模型目录当时为空，下载尚未开始。

## 二、排查结论

Windows 用户级 Internet Settings 已启用手动代理，代理地址为 `127.0.0.1:7897`。通过这个代理请求 `https://huggingface.co` 返回 HTTP 200，说明本机代理可用。

当前进程没有设置 `HTTP_PROXY`、`HTTPS_PROXY` 等代理环境变量，WinHTTP 代理也显示直连。浏览器使用 Windows 用户级代理，而 Node.js 22 的内置 `fetch` 不会自动读取 WinINET 的代理设置，因此 Transformers.js 的请求绕过代理，直接连接 Hugging Face 并超时。npm 配置中的 npm 镜像只影响 npm 包下载，不会代理模型文件请求。

## 三、修复内容

1. 将 `undici` 声明为项目直接依赖，并用 `EnvHttpProxyAgent` 为 Node `fetch` 配置代理调度器。
2. 模型下载命令先读取 `HTTP_PROXY`、`HTTPS_PROXY` 环境变量；未配置时，在 Windows 回退读取当前用户的 `ProxyEnable` 和 `ProxyServer` 注册表设置。
3. 代理配置只作用于本次模型下载进程，不修改 Windows、npm 或项目的代理设置。启动时打印代理来源和脱敏后的主机端口。
4. 模型下载完成或失败后关闭代理调度器。若连接仍超时，命令会提示检查代理是否能访问 `huggingface.co`。

Windows 使用自动代理脚本（PAC）、而不是 `ProxyEnable`/`ProxyServer` 手动代理时，需要在运行命令前设置 `HTTPS_PROXY`。其他系统也可以通过 `HTTPS_PROXY` 或 `HTTP_PROXY` 提供代理。

## 四、验证记录

在当前 Windows 环境完成验证：

1. 通过显式代理 `http://127.0.0.1:7897` 请求 `https://huggingface.co`，返回 HTTP 200。
2. 执行 `npm run models:download`，脚本检测到 Windows 用户代理并打印代理地址 `127.0.0.1:7897`。
3. `npm run models:download` 内部的 TypeScript 构建通过，随后三个模型均下载并加载完成，命令正常退出。
4. `data/models` 中生成 11 个模型文件，总计约 331 MB，包含多语言 CLIP 文本模型、CLIP 图片模型和中文分词模型。
