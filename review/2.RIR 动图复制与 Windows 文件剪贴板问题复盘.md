# RIR 动图复制与 Windows 文件剪贴板问题复盘

## 一、问题情况

RIR 远程图片复制功能曾出现以下现象：

1. 部分图片复制成功，部分图片提示“远程图片解码失败，无法写入剪贴板”。
2. 界面显示复制成功，但粘贴出来是“无法预览”，实际内容还是上一条有效的剪贴板内容。
3. 将远程图片统一转换为 PNG 后，复制虽然成功，但 GIF/WebP 动图只剩第一帧。
4. 改用 Windows 文件剪贴板后，又出现：

   ```text
   Windows file clipboard failed
   ArgumentException: filePaths 无效
   ```

## 二、排查过程

### 1. 排除网络和 RIR 服务异常

检查 RIR 地址和图片资源后确认：

- RIR 清单请求返回 HTTP 200；
- 图片资源请求返回 HTTP 200；
- 服务端提供了正确的图片响应头和跨域响应；
- 当前 RIR 清单共 180 张图片，均可由 `sharp` 正常解析。

因此，问题不是 RIR 地址失效，也不是所有图片文件损坏。

### 2. 定位 Electron 原生图片解码问题

原始实现直接执行：

```ts
const image = nativeImage.createFromBuffer(imageBuffer);
clipboard.writeImage(image);
```

Electron 的 `nativeImage` 对部分 GIF、动图 WebP 和特殊图片编码的原始解码不稳定。解码失败时会得到空图片，原代码没有充分校验，就可能出现提示成功但剪贴板仍保留旧内容的情况。

### 3. 定位“只能复制第一帧”的原因

后续实现将图片转为 PNG：

```ts
const pngBuffer = await sharp(imageBuffer, { animated: false })
  .png()
  .toBuffer();
```

该处理会取动图的第一帧。虽然之后又尝试写入 HTML 动图数据：

```ts
clipboard.write({
  image, // 第一帧 PNG
  html: `<img src="data:image/gif;base64,..." />`,
});
```

但大多数 Windows 桌面软件粘贴图片时优先读取静态图片格式，忽略 HTML 格式，所以最终仍然只得到第一帧。

### 4. 定位 Windows 文件剪贴板报错

Windows 文件剪贴板通过 PowerShell 的 `Clipboard.SetFileDropList()` 写入。最初命令使用了错误的环境变量语法：

```powershell
$env.IMGM_CLIPBOARD_FILE
```

PowerShell 读取环境变量的正确语法是：

```powershell
$env:IMGM_CLIPBOARD_FILE
```

错误写法得到的是空值，传给 `SetFileDropList()` 的文件路径为空，因此触发 `ArgumentException: filePaths 无效`。

## 三、最终解决方案

### 1. 静态图片

静态图片仍然按照以下流程处理：

1. 主进程下载远程图片；
2. 使用 `sharp` 解码并转换为 PNG；
3. 使用 `nativeImage.createFromBuffer()` 创建静态图片；
4. 使用 `clipboard.writeImage()` 写入剪贴板。

### 2. GIF/WebP 动图

Windows 下检测到多帧图片后，不再把第一帧 PNG 作为主要剪贴板内容，而是：

1. 将原始 GIF/WebP 字节保存到：

   ```text
   %TEMP%\imgm-rir-clipboard\
   ```

2. 按原始格式生成 `.gif` 或 `.webp` 文件；
3. 启动隐藏的 Windows PowerShell 子进程；
4. 使用 `System.Windows.Forms.Clipboard.SetFileDropList()` 写入 Windows `CF_HDROP` 文件剪贴板格式；
5. 临时文件保留 24 小时，避免目标软件粘贴时文件已经被删除；
6. 清理超过 24 小时的旧临时文件。

核心 PowerShell 逻辑如下：

```powershell
Add-Type -AssemblyName System.Windows.Forms
$paths = New-Object System.Collections.Specialized.StringCollection
[void]$paths.Add($env:IMGM_CLIPBOARD_FILE)
[System.Windows.Forms.Clipboard]::SetFileDropList($paths)
```

### 3. 非 Windows 平台

非 Windows 平台保留 HTML 动图作为兼容回退方案，因为 `CF_HDROP` 是 Windows 文件剪贴板格式。

## 四、验证结果

- 当前 RIR 的 180 张图片均可被 `sharp` 解析；
- 检测到 GIF、WebP 以及多帧动图；
- Windows `SetFileDropList()` 在 PowerShell 子进程退出后仍能保留文件列表；
- `npm test` 通过，10 项测试全部成功；
- 关键修改已加入 Git 暂存区。

## 五、使用说明与限制

修改后需要重新构建并启动应用：

```bash
npm start
```

动图现在以文件形式写入剪贴板。目标软件可能表现为“粘贴 GIF 文件”或“添加文件附件”，这是文件剪贴板的正常表现。只要目标软件支持 GIF 文件，就可以保留完整动画。

如果目标软件仍然只显示第一帧，说明该软件没有读取文件剪贴板，而是强制按静态图片方式处理，这属于目标软件的粘贴策略限制。
