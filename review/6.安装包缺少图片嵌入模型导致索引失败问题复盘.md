# 安装包缺少图片嵌入模型导致索引失败问题复盘

## 一、问题现象

安装器安装完成后，打开“索引图片”弹窗，选择图片并点击“应用”时，主进程报错：

```text
Error invoking remote method 'applyImageIndexSelection':
TypeError: Cannot read properties of undefined (reading 'tokenizer_class') · 0/0
```

开发环境中可以正常建立图片索引，但安装后的应用无法处理任何文件，进度显示为 `0/0`。

## 二、问题原因

### 1. 索引图片时不只需要图片模型

`applyImageIndexSelection` 会同时为图片文件名生成文本向量，相关调用链如下：

```text
applyImageIndexSelection
  -> embedTexts(图片文件名)
  -> initTextModel
  -> AutoTokenizer.from_pretrained(..., local_files_only: true)
```

因此，首次索引图片时会先加载文本模型。如果文本模型没有在安装包中，`AutoTokenizer` 无法读取本地模型配置，最终在 Transformers.js 内部读取 `tokenizer_class` 时出现 `undefined` 错误。

`0/0` 不是说明用户没有选择图片，而是任务在加载嵌入模型阶段就已经失败，尚未进入文件处理循环。

### 2. 安装包原本排除了 `data`

项目默认模型位于：

```text
data/models/
```

而 `electron-builder.yml` 的 `files` 配置明确排除了整个 `data` 目录：

```yaml
- '!data{,/**/*}'
```

这可以避免把开发环境数据和数据库打进 `app.asar`，但也会把本地嵌入模型一起排除。安装后的应用因此没有可供 `local_files_only: true` 加载的模型文件。

## 三、最终修改

### 1. 在 `electron-builder.yml` 中单独携带模型目录

没有取消对整个 `data` 目录的排除，而是只将模型目录复制到安装包的资源目录：

```yaml
extraResources:
  - from: data/models
    to: models
```

打包后模型实际位于：

```text
<安装目录>\resources\models
```

这样既不会把本地数据库、缓存和其他运行数据打包进去，也能携带应用运行所需的嵌入模型。

当前携带的默认模型包括：

```text
aurantium/clip-ViT-B-32-multilingual-v1  # 文本模型
Xenova/clip-vit-base-patch32             # 图片模型
```

### 2. 在 `src/main.ts` 中设置安装包运行时模型路径

开发环境继续使用默认的：

```text
data/models
```

只有打包后的应用才自动切换到 Electron 的资源目录：

```ts
function configurePackagedModelCache(): void {
  if (app.isPackaged && !process.env.IMAGE_MODEL_CACHE_DIR) {
    process.env.IMAGE_MODEL_CACHE_DIR = path.join(process.resourcesPath, "models");
  }
}
```

这段逻辑在 AI 模块加载前执行，因此 `src/ai/transformers-config.ts` 读取到的模型缓存目录会变为：

```text
process.resourcesPath\models
```

如果用户自己设置了 `IMAGE_MODEL_CACHE_DIR`，程序保留用户配置，不覆盖它。

### 3. 没有修改模型 ID 配置

本次修复没有修改 `TEXT_MODEL_ID` 或 `IMAGE_MODEL_ID`。它们仍然可以通过 `.env` 覆盖，默认值保持为：

```text
TEXT_MODEL_ID=aurantium/clip-ViT-B-32-multilingual-v1
IMAGE_MODEL_ID=Xenova/clip-vit-base-patch32
```

需要注意：如果通过 `.env` 改用了其他模型，必须同时确保对应模型文件也存在于 `IMAGE_MODEL_CACHE_DIR` 指向的目录中，否则仍会因为本地模型缺失而失败。

## 四、验证过程

重新执行 Windows 安装器构建：

```powershell
npm run make
```

并确认生成的安装包内部存在：

```text
resources\models\aurantium\clip-ViT-B-32-multilingual-v1\...
resources\models\Xenova\clip-vit-base-patch32\...
```

在打包后的运行环境中调用文本嵌入测试，成功返回 512 维向量；随后重新执行图片索引流程，不再出现 `tokenizer_class` 错误。

## 五、后续打包注意事项

1. 修改 `data/models` 中的模型文件后，需要重新执行 `npm run make`，旧安装包不会自动获得新模型。
2. 分发给其他用户时，应分发重新生成的 `out\\installer\\IMGM-Setup.exe`。
3. 不要为了携带模型而直接删除 `files` 中的 `!data{,/**/*}`，否则可能把本地数据库、缓存和其他开发数据一并打进安装包。
